# 小玩意儿 Playroom

九款可以直接在浏览器游玩的轻量小游戏。纯静态站点，无需后端、数据库或第三方 API。


## 新版：背包守夜人 · 永夜防线

**在线入口：** https://klwjlalala.github.io/games/prototypes/nightwatch/

原来的五晚数值结算原型仍保留在 `/prototypes/` 作为对照。新版是独立、可持续挑战的背包塔防：

- 真实 Canvas 三路冲锋：怪物会接近城门，武器发射弹道；拥有血条、伤害飘字、范围爆炸、燃烧、中毒和冰霜减速。
- 5×4 背包：选择装备并点击格子摆放；增益材料必须与攻击装备相邻才能触发。
- 15 条可见合成配方：基础件重铸、元素分支、终极机关。合成消耗两件材料与金币，成品需重新摆放。
- 8 种敌人图鉴：成群掠粮鼠、高速暮影蝠、重甲虫、狂暴狼、治疗祭司、物理抗性游魂、破城巨兽、每五波出现的永夜龙。
- 波次中自动战斗，波次间领战利品、买补给、修城门、合成装备。挑战无限波次并保存最佳成绩与怪物图鉴。
- 本地无需模型或账户，不上传游戏数据到后端。

**装备合成路线示例：** 守夜弓＋守夜弓 → 风暴连弩；连弩＋火种 → 烈焰连弩；连弩＋凝霜晶 → 永霜连弩。法杖双合成雷击法杖后还可以分支毒云与天火炮，盾牌双合成城防壁垒后分支冰棘城塞与熔火城墙，最终可合成末日天幕和极光机关。游戏中的「配方图」展示全部具体材料与金币成本。

**可复现测试：**
```bash
node prototypes/nightwatch/simulate.cjs
npx playwright test prototypes/nightwatch/nightwatch.spec.cjs --workers=1
```
第一条完全不需要第三方包。第二条需要本地启动HTTP静态服务器并安装Playwright及Chromium；仓库的 GitHub Actions `.github/workflows/gameplay-test.yml` 已负责自动运行它们。

## 游戏列表

### 原有六款
1. **最后一车** — 空间装箱：旋转并摆放货物，填满车厢。
2. **拆迁队：最后一铲** — 爆破解谜：有限炸药清除建筑方块。
3. **茶汤有度** — 容量推理：在不同容量的杯子间倒水，达到目标水位。
4. **旧物修复所** — 清洁与配件匹配：擦去灰尘，安装正确零件。
5. **地底 100 层** — 反应挑战：切换轨道，躲避障碍并收集矿晶。
6. **玄岳背上的小森林** — 生态布局：安排地形，满足相邻与连通条件。

### 新增三款
7. **梦境拼接师** — 选择梦境题签，把物品拖入梦境空间；探索隐藏组合，生成可分享的梦境卡片。
8. **深夜便利店** — 接待三位深夜顾客，从货架挑选三件商品组成补给袋；不同选择会改变顾客的回应与最终夜班报告。
9. **宇宙售后服务中心** — 处理三张荒诞工单；调查现场的三个线索，再选择修复方案，查看宇宙客服值班评级。

## 本地运行

在项目目录执行：

```bash
python -m http.server 8080
```

然后访问 `http://localhost:8080`。

## 技术说明

- 原生 HTML / CSS / JavaScript，静态部署，无需构建步骤
- 不依赖外部图片、模型 API 或第三方运行时
- 游戏进度保存在浏览器 `localStorage`（原有游戏）
- 新增三款游戏使用本地状态，刷新后重新开始
- 桌面端支持鼠标操作，新增游戏也适配触屏点击


## 机制优先可玩性实验（2026-11）

直接访问 **https://klwjlalala.github.io/games/prototypes/** 可试玩两款独立原型：

- **十步突围**：7×7 棋盘、10 次行动、敌人下一回合攻击预告、冲刺与推击、三片递进封锁区、随机障碍和关间补给选择。
- **背包守夜人**：4×3 背包装备空间、邻接联动、五夜自动战斗、三选一奖励、实时数值预览。

这两款原型用于验证机制与重玩动机，不代表经过真实玩家测试的正式成品。原有九款保持不变。


### 回归与对抗性检查

- `node prototypes/adversarial-tests.cjs`：直接调用游戏规则，做地图可达性、炮台遮挡、技能拾取、装备联动与策略对照测试。
- `prototypes/playtest.spec.cjs`：Playwright Chromium 交互测试，覆盖页面切换、棋盘操作、补给选择、背包摆放、战斗和重置。
- GitHub Actions：`.github/workflows/gameplay-test.yml`，每次更新原型会触发上述两类检查。
- 评审结论与局限：`prototypes/PLAYTEST_REPORT.md`。自动化只能证明规则与交互可靠性，不能替代真实玩家对可玩性的判断。
